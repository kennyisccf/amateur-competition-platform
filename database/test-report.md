# 乐赛数据库测试报告

## 1. 测试目标

验证 `database/lesai.sql` 能够创建当前系统所需数据表、字段和样例数据，并支撑登录、赛事、报名、赛程、好友、通知和积分等业务。

## 2. 数据库环境

| 项目 | 内容 |
| --- | --- |
| 数据库 | MySQL 8.0 |
| 数据库名 | `lesai_db` |
| 字符集 | `utf8mb4` |
| 初始化脚本 | `database/lesai.sql` |
| 升级脚本 | `database/upgrade_registration_fields.sql` |

## 3. 表结构验证

| 表 | 验证点 | 结果 |
| --- | --- | --- |
| `user` | 用户编号、角色、积分、封禁、好友申请开关 | 通过 |
| `competition` | 赛事编号、状态、邀请码、缩图、淘汰树状态 | 通过 |
| `registration` | 报名唯一约束、审核状态、成绩和档案可见性 | 通过 |
| `point_history` | 积分流水记录 | 通过 |
| `audit_record` | 管理员审核记录 | 通过 |
| `notice` | 赛事通知 | 通过 |
| `friend_relation` | 好友申请和好友关系 | 通过 |
| `friend_message` | 好友聊天与未读消息 | 通过 |

## 4. 约束验证

| 场景 | 预期 | 结果 |
| --- | --- | --- |
| 重复用户名 | 被唯一约束阻止 | 通过 |
| 同一用户重复报名同一赛事 | 被唯一约束阻止 | 通过 |
| 赛事编号重复 | 被唯一约束阻止 | 通过 |
| 好友关系重复申请 | 通过唯一关系约束控制 | 通过 |

## 5. 样例数据验证

初始化脚本包含：

- 2 个管理员账号：`admin`、`test_admin`
- 1 个主办方账号：`org_zs`
- 3 个参赛者账号：`player_mike`、`player_jane`、`player_test`
- 赛事状态覆盖：待审核、报名中、进行中、已结束、已驳回
- 私人赛事邀请码：`LESAI6`
- 默认缩图路径：`/default-thumbnails/...`

所有账号密码均为 `123456` 的 MD5 值。

## 6. 结论

当前数据库结构与 Django `models.py` 中的 `managed = False` 模型保持一致，能够支撑系统本地运行和功能验收。旧版数据库测试报告中的 6 张核心表已扩展为 8 张业务表，新增了好友关系、好友消息、赛事缩图、用户编号和淘汰树状态等字段。
