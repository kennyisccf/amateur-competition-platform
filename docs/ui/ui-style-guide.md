# 乐赛 UI 视觉与组件规范

## 1. 设计定位

乐赛面向校园和社区业余赛事场景，界面风格应体现：

- 清爽、可信、赛事平台感。
- 信息密度适中，适合反复管理和业务验证。
- 参赛者页面偏轻量浏览，主办方/管理员页面偏后台效率。
- 避免纯营销式页面，业务页面优先展示可操作数据。

## 2. 色彩规范

| 角色 | 颜色 | 用途 |
| --- | --- | --- |
| 品牌蓝 | `#1677ff` / `#1e80ff` | 主按钮、导航、强调 |
| 深墨色 | `#0f172a` | 标题、重点文字 |
| 背景浅灰 | `#f5f7fb` | 页面背景 |
| 卡片白 | `#ffffff` | 内容区域 |
| 成功绿 | `#52c41a` | 报名中、通过、成功 |
| 警告橙 | `#fa8c16` | 私人赛、待审核、提示 |
| 错误红 | `#f5222d` | 驳回、删除、失败 |

## 3. 字体排版

| 层级 | 建议 |
| --- | --- |
| 字体族 | `PingFang SC`, `Microsoft YaHei`, sans-serif |
| 页面大标题 | 26-36px，加粗 |
| 模块标题 | 18-22px，加粗 |
| 正文 | 14-16px |
| 表格/辅助信息 | 12-14px |

## 4. 组件规范

### 4.1 按钮

- 主操作使用蓝色实心按钮。
- 删除、驳回等危险操作使用红色按钮。
- 次级操作使用描边或浅色按钮。
- 图标按钮用于刷新、返回、搜索、编辑等明确操作。

### 4.2 卡片

- 赛事卡片展示缩图、状态、分类、时间、人数进度。
- 卡片圆角控制在 8-12px。
- Hover 可轻微上浮，但不影响阅读。

### 4.3 表格

- 后台表格优先展示状态、人数、审核、操作。
- 操作按钮保持短标签，如“查看”“修改”“报名管理”“驳回”。
- 批量操作应放在表格上方工具栏。

### 4.4 状态标签

| 状态 | 样式 |
| --- | --- |
| 报名中 | 绿色 |
| 待审核 | 橙色 |
| 进行中 | 蓝色 |
| 已结束 | 灰色 |
| 已驳回 | 红色 |
| 私人赛 | 橙色 |
| 公开赛 | 绿色/蓝色 |

## 5. 图片规范

- 赛事缩图优先使用 `frontend/public/default-thumbnails/` 下的默认图。
- 创建/编辑赛事支持本地上传。
- 赛事卡片图片应保持居中裁切，避免只露出边角。
- 登录/注册页背景使用多张运动/赛事氛围图随机分布，保持同一视觉风格。

## 6. 响应式规范

- 主体布局应适配浏览器宽度变化。
- 赛事卡片使用自适应网格。
- 详情页和后台页避免固定超宽内容撑破页面。
- 淘汰树允许横向滚动，但节点不能重叠。
