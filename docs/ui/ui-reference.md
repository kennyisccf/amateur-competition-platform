# 乐赛 UI 参考说明

## 1. 产品类型参考

乐赛属于赛事组织平台，视觉参考不应完全偏营销落地页，而应接近“赛事大厅 + 管理后台 + 社交通知”的组合产品。

## 2. 参考方向

| 类型 | 参考点 | 在乐赛中的体现 |
| --- | --- | --- |
| SaaS 后台 | 清晰导航、状态表格、工具栏 | 赛事工作台、报名管理、管理员审核 |
| 体育赛事平台 | 赛事卡片、赛程树、比分状态 | 赛事大厅、淘汰树、比赛结果 |
| 社交产品 | 好友列表、聊天未读、通知中心 | 好友系统、消息通知 |
| 资料档案页 | 个人信息、积分、历史记录 | 个人运动档案 |

## 3. 页面设计原则

- 首页和赛事大厅优先让用户快速找到赛事。
- 赛事详情页优先展示报名状态、时间、规则和入口。
- 报名管理页优先支持批量操作和高密度扫描。
- 淘汰树页优先保证结构清晰和节点不重叠。
- 通知中心优先突出待处理项。
- 管理员页面优先突出审核、风控和批量治理。

## 4. 不采用的方向

- 不做纯宣传型首页。
- 不使用过多装饰性渐变和大面积无意义卡片。
- 不把后台页做成低密度海报式布局。
- 不使用需要外网加载的图片链接作为赛事缩图核心方案。

## 5. 最终视觉特征

- 蓝白主色，信息清晰。
- 默认赛事缩图统一风格。
- 登录/注册页有随机背景图，避免单调。
- 业务页面重视表格、筛选、状态标签和批量操作。
- 高频业务页面尽量减少跳转成本。
