# 文档体系说明

## 1. 目的

本文档用于说明乐赛项目当前交付文档的组成、适用范围和维护原则，帮助开发者、测试人员和项目维护者快速判断哪些文档应作为当前版本的依据。

当前文档以代码库、数据库脚本和可运行系统为准，重点覆盖：

- 本地部署与运行。
- 功能范围与角色权限。
- API 接口与数据结构。
- 数据库表结构与状态码。
- 单淘汰树核心算法。
- 测试范围与验证结果。
- UI 页面结构与视觉规范。

## 3. 文档维护原则

1. 以当前代码为准
   文档中的功能、接口、字段和运行步骤必须与当前仓库一致，不记录尚未实现的规划功能作为当前能力。

2. 以可运行流程为准
   运行说明应覆盖数据库初始化、后端启动、前端启动和检查命令，避免只写概念说明。

3. 以业务边界为准
   功能说明应明确参赛者、主办方、管理员的职责边界，避免把权限未开放的操作写成普通用户能力。

4. 以状态一致性为准
   赛事状态、报名状态、淘汰树状态、通知状态等说明应和后端接口及数据库字段保持一致。

5. 历史规划与当前交付分离
   未落地的规划、外部集成和商业化能力可以作为后续规划记录，但不应混入当前交付说明。

## 4. 已剔除的过时表述

当前版本已将早期文档中的以下不准确或未落地内容从最终说明中剔除：

- Bearer Token / SimpleJWT 鉴权描述。
- Django REST Framework 作为核心接口框架的描述。
- Spring Security / JJWT 等非本项目技术栈。
- Apache POI 导入导出。
- 外部机构接口对接。
- 完整段位系统。
- 投票决定新增赛事项目。
- 支付、实名验证等商业化扩展。

## 5. 推荐阅读顺序

新成员或维护者建议按以下顺序阅读：

1. `README.md`
2. `docs/run-guide.md`
3. `docs/feature-overview.md`
4. `database/database-design.md`
5. `docs/api.md`
6. `docs/bracket-design.md`
7. `docs/test/test-report.md`

## 6. 更新要求

当代码发生以下变化时，应同步更新文档：

- 新增或删除 API。
- 修改数据库表结构或状态码。
- 调整角色权限。
- 修改赛事、报名、通知或淘汰树状态流转。
- 新增前端页面或改变主要路由。
- 修改本地运行方式或依赖版本。
